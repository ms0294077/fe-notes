# UML

> [!summary] 一句話
> UML 是用圖形表示軟體結構與行為的標準記法；題目重點是依用途選擇正確的圖。

## 主要圖的用途

| 圖 | 用途 | 題目關鍵詞 |
|---|---|---|
| クラス図 | 類別、屬性、方法與關係 | 静的構造、継承 |
| オブジェクト図 | 某時點的物件實例 | インスタンス |
| ユースケース図 | 使用者與系統功能 | アクター、要求 |
| シーケンス図 | 依時間順序表示訊息交換 | 時系列、メッセージ |
| コミュニケーション図 | 物件關係與訊息 | 相互作用 |
| アクティビティ図 | 工作或處理流程 | 分岐、並行 |
| ステートマシン図 | 物件狀態與轉換 | イベント、状態 |
| コンポーネント図 | 軟體元件與依賴 | 部品 |
| 配置図 | 軟硬體節點的部署 | ノード、実行環境 |

## クラス図的關係

- 継承／汎化：is-a
- 集約／コンポジション：part-of
- 関連：物件之間的一般關係
- 依存：一方暫時使用另一方

## 判斷方法

- 「誰使用什麼功能」：ユースケース図
- 「誰先傳訊息」：シーケンス図
- 「處理步驟」：アクティビティ図
- 「狀態如何改變」：ステートマシン図
- 「類別如何組成」：クラス図
- 「系統部署在哪些設備」：配置図

## FE考點

- クラス図是静的構造
- シーケンス図與コミュニケーション図都是相互作用図
- アクティビティ図可表現分岐與並行
- ステートマシン図重點是事件造成狀態轉換

## 易錯點

- E-R図不是UML，但都可表現資料關係
- DFD表示資料流，不等於アクティビティ図
- ユースケース圖不描述內部處理順序

## 快速記憶

> 結構看class，時間看sequence，流程看activity，狀態看state，需求看use case。
