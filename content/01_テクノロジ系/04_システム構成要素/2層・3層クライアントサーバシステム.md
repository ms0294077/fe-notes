# 2層・3層クライアントサーバシステム

> [!summary] 一句話
> 2層由client直接連DB；3層加入application server，較容易集中管理與擴充。

## 2層構成

client ↔ database server

client通常負責：

- 畫面
- 業務邏輯
- DB存取要求

### 優點

- 結構簡單
- 小規模系統容易建立
- 通訊路徑短

### 缺點

- client較重
- 版本更新分散
- 大量client直接連DB，擴充與安全管理較困難

## 3層構成

client ↔ application server ↔ database server

| 層 | 主要工作 |
|---|---|
| プレゼンテーション層 | 畫面與輸入輸出 |
| ファンクション層 | 業務邏輯 |
| データ層 | DB保存與查詢 |

### 優點

- 業務邏輯集中管理
- client較輕
- 容易擴充與負載分散
- DB不必直接公開給所有client

### 缺點

- 結構與部署較複雜
- application server也要做可用性設計

## Webシステム的典型構成

browser ↔ Web／application server ↔ DB server

browser主要負責表示，業務處理由server執行。

## FE考點

- client直接連DB：2層
- 中間有業務邏輯server：3層
- 業務邏輯集中：3層
- 導入中間層不代表故障點自動消失，需要冗餘設計

## 快速記憶

> 2層是client與DB；3層在中間加業務處理。
