# トランザクションとACID特性

> [!summary] 一句話
> ACID＝Atomicity、Consistency、Isolation、Durability。

## トランザクションとは

**トランザクション（Transaction，交易）**是：

> 資料庫操作中，必須視為一個整體的一連串處理。

例如 ATM 轉帳：

```text
自己的帳戶扣款
＋
對方的帳戶加款
＝
一個完整的交易
```

不能只完成其中一半。

## ACID特性

資料庫執行交易時，必須滿足四個特性。

| 特性 | 中文 | 重點 |
|---|---|---|
| Atomicity | 原子性 | 全部完成，或全部取消 |
| Consistency | 一致性 | 資料不能矛盾 |
| Isolation | 隔離性 | 多個交易不能互相干擾 |
| Durability | 耐久性 | 成功後的資料不能消失 |

### 快速記法

```text
A：不做一半
C：不能矛盾
I：互不干擾
D：成功不消失
```

## Atomicity（原子性）

交易只能有兩種結果：

```text
全部成功
或
全部取消
```

例如轉帳時：

```text
A帳戶 −10,000
B帳戶 ＋10,000
```

如果中途失敗，就要使用：

- **用語：** ロールバック（Rollback，回滾）
恢復到交易開始前的狀態。

## Consistency（一致性）

交易前後，資料庫都必須符合規則、不能產生矛盾。

例如：

- 主鍵不能重複
- 主鍵不能是 NULL
- 庫存不能小於 0
- 轉帳前後總金額不能憑空增減

## Isolation（隔離性）

即使多個交易同時執行，也不能互相影響。

例如帳戶原本有 100 萬：

```text
交易1：存入20萬
交易2：存入30萬
```

正確結果：

```text
100萬＋20萬＋30萬＝150萬
```

如果兩個交易同時讀到原本的100萬，可能分別寫回120萬和130萬，導致其中一次更新消失。

這叫：

> 更新遺失

## Durability（耐久性）

交易一旦成功完成，即使之後發生：

- 停電
- 系統當機
- 網路中斷

已經保存的結果也不能消失。

通常會利用：

- ログ（Log，日誌）
- バックアップ（Backup，備份）

來保護資料。
