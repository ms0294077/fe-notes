# RASIS（システム評価特性）

> [!summary] 一句話
> RASIS＝Reliability、Availability、Serviceability、Integrity、Security，是評估系統品質的五個面向。

RASIS 是用來評估系統品質的五個指標。

## R：Reliability（信頼性）
中文：**可靠性**

- 系統能否長時間穩定運作
- 是否不容易發生故障
- 使用 **MTBF** 評估

```text
MTBF 越大 → 越不容易故障
```

## A：Availability（可用性）
中文：**可用性**

- 想使用系統時，是否能正常使用
- 使用「稼動率」評估
- 故障少、修復快，可用性就越高

## S：Serviceability（保守性）
中文：**可維修性**

- 系統故障後，能否快速修復
- 使用 **MTTR** 評估

```text
MTTR 越小 → 修復速度越快
```

## I：Integrity（保全性）
中文：**完整性／資料保全性**

- 資料是否正確、完整
- 防止資料遺失或遭到不當修改

例如：銀行帳戶餘額不能無故改變。

## S：Security（安全性）
中文：**安全性**

- 防止未授權存取
- 防止網路攻擊與資料外洩
- 維持系統和資料的安全

## MTBF
全名：

- **用語：** Mean Time Between Failures
中文：**平均故障間隔時間**

代表：

系統從一次故障修好後，到下一次故障發生前，平均能正常運作多久。

例如某系統正常運作：

```text
500小時 → 故障 → 修復 → 700小時 → 故障
```

MTBF：

```text
(500＋700) ÷ 2 ＝ 600小時
```

因此：

```text
MTBF 越大越好
＝正常運作時間長
＝不容易故障
```

## MTTR
全名：

- **用語：** Mean Time To Repair
中文：**平均修復時間**

代表：

系統發生故障後，平均需要多少時間才能修復。

例如兩次故障分別花：

```text
2小時、4小時
```

MTTR：

```text
(2＋4) ÷ 2 ＝ 3小時
```

因此：

```text
MTTR 越小越好
＝修復時間短
＝比較容易維修
```

## MTBF與MTTR比較
|**指標**|**中文**|**評估內容**|**趨勢**|
|---|---|---|---|
|MTBF|平均故障間隔時間|多久才故障一次|越大越好|
|MTTR|平均修復時間|故障後多久修好|越小越好|

## FE考點
```text
R：不容易壞 → MTBF越大越好
A：想用就能用
S：壞了容易修 → MTTR越小越好
I：資料不能亂
S：防止攻擊
```

```text
MTBF：壞掉之間隔多久
MTTR：壞掉後修理多久
```
